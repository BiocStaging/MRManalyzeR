# How the bundled data was made

Everything in `inst/extdata` is listed here with where it came from. The
scripts that generate it live in this directory.

## `example_data.xlsx` — the real dataset

A subset of the targeted oxylipin panel published in

> Kolmert J. *et al.* (2018). Lipid mediator quantification in isolated human
> and guinea pig airways: an expanded approach for respiratory research.
> *Prostaglandins & Other Lipid Mediators* **137**, 11–18.
> <https://doi.org/10.1016/j.prostaglandins.2018.05.005>

exported from Waters TargetLynx and cut down to a size that suits a package
example. The workbook holds the three sheets the package reads:

| Sheet | Contents |
|---|---|
| `lcms_data` | the TargetLynx export, one block per compound |
| `sample_metadata` | one row per injection: inclusion flag, sample type, batch, volumes |
| `feature_metadata` | one row per compound: reporting flag, class and pathway annotation |

The two metadata sheets are curation, written by hand: which injections to
include, which compounds were reviewed and kept, and the class and pathway
each compound belongs to. No step of the package writes them.

## `example_synthetic.xlsx` and `example_synthetic.RDS` — simulated

Generated by [`make_example_synthetic.R`](make_example_synthetic.R) in this
directory. Nothing in them is measured: every value is simulated from a fixed
seed, so the files can be rebuilt exactly.

```r
devtools::load_all()
source("inst/script/make_example_synthetic.R")
```

The script writes the Skyline-layout workbook and the processed
`DatasetExperiment` beside it. It exists because the real workbook above
cannot exercise the whole workflow: it is one chromatographic batch, one
reconstitution volume per vial, and has no per-sample amount, so batch
correction, normalisation and concentration adjustment would all be no-ops.
What the simulation plants deliberately — a treatment effect on 5 of 20
analytes, a batch shift, QC noise below biological noise, signal proportional
to a protein amount — is documented in the script's header, and recorded in
the workbook so the documentation can show each step recovering something
known.

## `example_config.yml` and `example_combine_config.yml` — written by hand

The reference configurations, documenting every key and its allowed values.
`example_config.yml` drives [`mrmRunExample()`](../../R/run_example.R) against
`example_data.xlsx`; `example_combine_config.yml` shows the shape of a
merge-several-panels run. Neither is generated.

## `TargetLynx_Layout.qlt` — a vendor file

The TargetLynx report layout that produces an export in the format
`readTargetLynx()` expects. Saved from MassLynx and included so the expected
column set can be reproduced rather than guessed at.
